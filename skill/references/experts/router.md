# MoE 路由门控（router）

专家不是固定名单，而是按需激活的稀疏组合。本文件定义：门控怎么算、常驻专家怎么组、微专家怎么召唤。

## 门控（gating）

**输入**
1. 类型分类（主/副类型 + 权重，来自 01-meta/classification.md）
2. 正文内容信号：目录 + 抽样正文中检测到的**具体议题/知识点**（如"量子力学""货币政策""安史之乱""神经网络"）
3. 宇宙碰撞结果：universe/index.md 中相关的已有书/概念节点
4. 人格档案（可选）：兴趣焦点可作为深度加权参考

**输出：专家激活清单**（写进确认点 A 的呈现里）

```markdown
## 专家激活清单 —《三体》
| 专家 | 类型 | 聚焦 | 深度 |
|---|---|---|---|
| 叙事结构学家 | 常驻(fiction) | 三部曲结构、多线交织 | 全书 |
| 人物关系分析师 | 常驻(fiction) | 叶文洁/罗辑弧光、面壁者群像 | 全书 |
| 文体语言分析师 | 常驻(fiction) | 硬科幻语域、宏大叙事节奏 | 全书 |
| 主题象征分析师 | 常驻(fiction) | 黑暗森林、宇宙社会学 | 全书 |
| 宇宙学微专家 | 动态储备 | 三体问题、维度设定 | 按需召唤 |
| 时空审计员 | 动态储备 | 文革背景段落的史实核对 | 按需召唤 |
| 红队审稿人 | 通用 | 全书批判性审计 | 全书 |
召唤预算：每阶段 ≤3，全书 ≤10
```

## 覆盖策略（防跳读遗漏）

专家跳读只覆盖全书 5-15%，存在系统性盲区风险（首拆实战验证：红队 13 条发现中 8 条为独立新增，说明单一专家盲区真实存在）。三层缓解，按性价比排序：

**第一层：全书测绘官（mapper，文件模式下必配）**
- Step 1 派子 agent 通读全书，产出 3-5k token 测绘图 `01-meta/book-map.md`：
  - 逐讲/逐章一行摘要（含行号）
  - **绝对化论断全量清单**：Grep「共识、必然、一定、肯定、永远、所有、毫无疑问、没有任何、唯一」等模式，每条带行号——批判的最优靶点
  - 概念出现密度表（哪个概念在哪几讲密集出现→专家定点深读的坐标）
  - 金句表（供 takeaway 复用）
- 专家 prompt 附上测绘图，从"盲读抽样"变为"全量索引 + 定点深读"
- **成本控制（实战教训：47 万字单 mapper 烧 11.27M token，占全书成本一半）**：
  - 全书 > 30 万字 → 章级单元切分卷 mapper（一章～几章一组、每单元约 8-20 万字、切点取结构边界；**切分前初扫描图、强关联簇不拆散**，规范见 stage1-research.md §1；各自产出分卷测绘图并**增量写入书内知识图谱 `01-meta/book-graph.md`**，主 agent 汇总成总图）——分块上下文不累积，总价可省 40%+
  - 结构规整的论著（讲义体、教材体）→ 允许"目录精测"降级：逐章读首尾段 + 绝对化论断 Grep 全量 + 概念密度抽样，成本约为全量 mapper 的 1/3——**适用面（实测固化）：结构规整的方法论书/教材体默认目录精测**（一本 9 章规整结构的方法论书实测 1.64M，对照全量 mapper 3.2-4.9M，下游专家零因降级投诉）；叙事密集或章内结构复杂的书（案例集、小说、论战集）仍用全量 mapper
  - **缺席清单**（先贤评审 2026-09-18 补）：mapper 附加产出——对照同领域 2-3 本标杆书的目录，列出「同类书都讨论、本书未讨论」的标准配置项（实战先例：薛书"市场失灵 0 次"系人肉发现，机制上应无人力依赖）。沉默与断言同样值得审计
  - 测绘图落盘即缓存：同一本书重拆（如补拆某一步）时直接复用 `01-meta/book-map.md`，不重派。**缓存是默认，不是义务（先贤评审 2026-09-18 修正）**：读者已显著进化（人格版本差 ≥4）或书后新证据出现时，**结论层应重拆**——测绘图与图谱可复用，level1/digest 不复用（同一本书对变了的人是另一本书）

**第二层：专责全读章（`--budget full` 时启用）**
- 给每位常驻专家分配 2-3 章"专责全读"（对该章全部内容负责），其余章按测绘图跳读——各专家专责章的并集 = 100% 覆盖

**第三层：红队缺口审计**
- 红队最后一项任务：对照测绘图检查各专家产出的章节覆盖密度，对零发现章节补抽样

## 微专家与常驻专家的分工边界（实战修正）

常驻专家 prompt 自带 WebSearch 许可，论断核实**内线完成**（首拆 7 专家平均 40 次工具调用，动态召唤零触发——这是合理状态）。微专家只用于：常驻专家覆盖不了的**领域知识补充**（如小说里的量子设定、经济书讲到货币政策），而非事实核查。

## 常驻专家组（按主类型，详见各档案）

| 主类型 | 常驻专家 |
|---|---|
| fiction | 叙事结构学家、人物关系分析师、文体语言分析师、主题象征分析师（+类型加成，见 fiction.md） |
| narrative | 叙事记者、史实核查员、史学把关人、传主研究者 |
| ideas | 论证分析师、**学术纪律审计员**（原「领域学术专家」实战升级合并，→ discipline.md：领域共识 + 免疫结构 + 复现折价 + 中译数字）、思想史定位员、反方辩手 |
| knowledge | **领域专家（动态实例化：按分类卡 + 内容信号定学科画像，跨学科按权重分派副域节，第三域缺口走微专家——见 knowledge.md）**、课程设计师（**学习路径型书限定**：方法论/教材/技能；通识问答集跳过）、实践教练；科学/社科类加配学术纪律审计员 |
| 通用加配 | **转译保真审计员**（译作/转述集成型/科普转译书——出处层失真、转译链归因、译名一致性）；**论证分析师与思想史定位员**在 ideas 副类型权重 ≥0.3 的 knowledge 书常配（实战 12 本中 10-11 本已如此产出，规范追认） |
| poetry/visual/practical | 见 arts.md（按需 1-3 名，轻量） |

通用附加（见 auditor.md）：**红队审稿人**每本必配；**时空审计员**按分类卡的特殊标记决定常驻或动态储备。学术纪律与转译保真两个编制专家的规范亦见 auditor.md。

## 动态召唤微专家（任意步骤可触发）

**触发条件（满足其一）**
1. 分析触达一个常驻专家**覆盖不了的具体知识点**（领域性强的概念、技术、事件）
2. 书中出现**领域知识空白**——需要背景补充才能评价的概念体系/技术/制度细节（是「不懂」，不是「真假存疑」；可检索的真假核实由常驻岗自带检索自查：红队、纪律审计、转译审计、时空审计均有 WebSearch 许可）
3. 红队/纪律审计把某论断标「存疑」，且裁决它需要**超出检索的专门知识**
4. 宇宙中已有相关概念节点，需要**跨书对照**的专门知识

**召唤流程**
1. 从触发点提取知识点（一个微专家只管一个知识点；相似知识点合并后召唤）
2. 派 general-purpose 子 agent，prompt 四段任务：**搜索核实 → 对照领域共识 → 评价书中处理 → 补充必要背景**
3. 产出**知识点卡**（模板见下）写到 `02-analysis/kp-<知识点slug>.md`
4. 记入本阶段召唤日志

**知识点卡模板**

```markdown
# 知识点卡：<知识点>
- 触发位置：[原文·章节/段落]
- 领域：<学科>
## 书中说法
（转述，不改写立场）
## 领域共识
（核实结论，标注 [网络·来源]）
## 评价
- 准确性：准确 / 简化但可接受 / 有偏差 / 有误（各附依据与置信度：确凿/存疑/个人判断）
- 该知识点与全书论点的关系
## 补充背景
（读者需要懂什么才能跟上这部分）
```

**预算与纪律**
- 每阶段默认上限 3-5 个，全书上限 10 个；超预算时合并或降级为"存疑标注"不召唤
- 阶段末向用户汇报召唤记录（谁、为什么、产出了什么卡）
- 微专家只写自己的卡，不碰其他文件、不碰宇宙
