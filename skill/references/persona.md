# 读者人格（persona）· 人格层规范

人由经历、读过的书、进行过的对话塑造。本规范让一个"数字读者"随每次拆书与每次书评交互进化。

**防僭越纪律（最高优先级）**：人格属于用户，AI 是镜子不是主人——起草权归 AI，定夺权归用户。**默认入库制（用户裁决 2026-09-18）**：人格更新提案与涌现候选不再逐项等待裁决，生成后直接写入 profile（标注「默认入库」），用户保留事后否决权（否决即移除并记 journal 一行，不再纠缠）；积累到阈值（约 20/50/100 条）时在 Dream 中做合并、归置、反驳整理。

## 目录

```
universe/persona/
├── profile.md   # 人格快照（带版本号，如 v3）
└── journal.md   # 进化日志（append-only：每次更新 = diff + 信号依据）
（提案归档于 universe/records/proposals/，命名 proposal-<yyyy-MM-dd>-v<N>-<slug>.md，落地后移 applied/）
```

## profile.md 维度

```markdown
# 读者人格 · v<N>
更新：<日期>（依据：《书X》拆书 + 《书Y》书评交互）

## 阅读谱系
（按主题域分布；只统计已拆的书）

## 品味画像
- 类型偏好：…
- 叙事/论证风格偏好：…
- 语言审美：…（例：喜欢克制短句，排斥排比堆砌）

## 思想立场
| 议题 | 立场 | 来源 | 演变 |
|---|---|---|---|
（立场必须带来源书；变化记演变轨迹，不抹旧账）

## 思维特征
（关注视角、提问习惯、常用概念工具——从拆书交互与书评讨论中提炼）

## 表达特征
（节奏、标点习惯、句式偏好、常用词与禁用词——逐段确认中用户的选择沉淀于此）
```

## 进化信号三源

1. **吸收**（step 4/7）：本书概念进入宇宙 → 阅读谱系与思维特征的工具箱扩展
2. **交互学习**（step 5，**最高价值信号**）：书评逐段确认中每次采纳/否决/修改 → `05-review/signals.md` 已静默记录 → 提炼为品味与表达特征的更新。用户否决某类改法 = 负信号，与采纳同样重要
3. **涌现**（step 3 生成候选，step 7 裁决）：宇宙碰撞产出的"合成观点"——把《X》和《Y》放在一起时才能冒出来的判断。模板：`观点 + 来源书目组合 + 涌现标记`。用户采纳 → 写入思想立场并注明「涌现自《X》×《Y》」；拒绝 → 只留 journal 一行"已否决"，不再提

## Step 7 流程

1. 汇总信号：本书吸收的概念清单、signals.md 的偏好记录、step 3 涌现候选（含用户在书评阶段临时表态过的）
2. 生成**人格更新提案**：profile.md 的 diff（改哪几行、加哪几行）+ 每处改动的信号依据 + 版本号 +1
3. ⏸ 确认点 C（汇报制）：提案**默认入库**（步骤 2 生成后直接写入），确认点改为汇报本轮入格内容，用户可当场或事后否决（否决项移除并记 journal 一行，不再纠缠）
4. journal.md 追加一条（含「默认入库」标注与事后否决通道）
5. **压缩条款（防膨胀，v4 实测 49 行仍可读，v8 将不可读）**：persona 版本号每逢偶数（v6/v8/…）或 Dream 时，把早期演变轨迹压缩——profile 只保留"现行特征 + 每条特征首现版本号"，完整历史 diff 移入 journal.md 归档；思想立场表不压缩（它是人格的本体）
6. **立场触达标记（Dream 时执行；用户裁决 2026-09-18：只标不删）**：思想立场表逐行标注最近触发场景/时间——知识、技能、观点都有触发条件，长期未触发≠应淘汰；反驳与合并提案由 Dream 合议生成、用户裁决，永不自动删除

## 人格反哺代谢

- **Step 5 书评**：profile.md 是初稿底色（口吻、立场、关注点）；表达特征节直接指导润色倾向
- **Step 1 门控**：人格的兴趣焦点可作为专家深度加权参考（router.md 输入之一）
- **品味漂移观察**：journal 按时间读即可见兴趣迁移（如近期从科幻偏向历史），可在确认点 C 主动告知用户"你的阅读宇宙最近在向 xx 倾斜"
