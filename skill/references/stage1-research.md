# Step 1 · 提取 + 并行调研

## 1. 输入解析与内容提取

**文件输入**（按格式选法，全部在本地处理）：

| 格式 | 提取方法 |
|---|---|
| PDF | 先试 `pdftotext <file> -`；不可用则 python pypdf 逐页提取。**扫描版（提取近乎为空）→ OCR 路径**（2026-09-17 模板已沉淀至 skill）：`swift <skill目录>/scripts/ocr.swift <input.pdf> <output.md> [起始页] [结束页]`——PDFKit 渲染 300dpi + Vision 中文识别（accurate + 语言纠正），流式写出，逐页标 `[OCR·p N]`；实测速度约 183 页/3 分钟。引用一律用 `[原文·OCR·p N]` 并在 metadata.md 顶部标注"OCR 可能有字词误识（例：卡尼曼→卡尼愛），关键引用回对页面"。实测样张：理论法学的迷雾（法律出版社 2008）全 186 页识别干净，术语（阿列克西/哈贝马斯）零误识 |
| EPUB | `unzip -o <file> -d <tmp>` 后按 OPF spine 顺序拼接 XHTML，去标签转文本（python html.parser 或 `textutil -convert txt`） |
| DOCX | macOS：`textutil -convert txt <file> -output -`；或 python-docx |
| TXT/MD | 直接读 |

提取结果写 `corpus/<书库分类层级>/<slug>/00-source/fulltext.md`（保留章节分隔标记）。

**合集/合订本拆分（先于一切处理）**：输入为套装、合集、多卷合一文件时（线索：版权页多个书名/ISBN、目录含多部独立编号作品、文件名含「套装/三本/合订」）→ **拆开为独立书目各自走完整流水线**，不把文件当一个整体：按书名页/目录边界切分（记录边界页码），每本各自 slug 与目录；共享的总序/附录归首书、两书 metadata 互注；合集不建总档，仅在 books-index 备注同组关联。拆分方案（几本、边界在哪）列入确认点 A 呈现；批量模式静默执行并记入 BATCH-PROGRESS。

**超长书分卷拆解（>30 万字）**：全文落盘后按书的结构边界（章/讲/部）切成卷单元——**一章～几章一组、每单元约 8-20 万字，切点取结构边界，不按字数硬切**。**切分前先初扫描图**：目录 + 各章首尾抽样 → 识别强关联章（同一论证链延续、同一概念密集共现、案例前后回引），**强关联簇不拆进不同单元**；切分后对照图谱复查跨单元强关联边，超阈值即调整切点——防止有依赖关系的章节被切散断链。流水线按「单元 → 汇总」两层执行：① 单元层：每卷一个分卷 mapper（规范同 router.md，各自产出分卷测绘图：论断清单/概念密度/金句，并**增量写入书内知识图谱**）；② 汇总层：主 agent merge 成总测绘图——跨卷主线、重复论断合并、全局概念密度与金句表——专家 prompt 附总图定点深读，digest 依总图写作。

**书内知识图谱 `01-meta/book-graph.md`**（分卷全程维护，防断链的核心设施；分卷 mapper 增量写入、汇总层 merge、**专家组实时可检索**——专家 prompt 一律附图谱与倒排索引，遇到跨单元引用〔概念后文重现、案例回引前文〕直接 Grep 定位原文，不必通读）：

```markdown
# 书内知识图谱
## 章节单元表（单元 → 章范围 → 一句话主题）
## 概念-章节倒排索引（概念 → 首次定义处[单元:行号] + 出现单元清单）
## 跨章关联边（单元A—单元B：论证延续/概念依赖/案例回引 + 一句依据）
## 强关联簇（切分依据存档：哪些章因什么不拆散）
```

merge 纪律：跨卷论断定位写「单元号+行号」；同一概念多卷出现时合并计数、保留首次定义处行号；跨单元关联边全部保留进总图，不许因 merge 丢弃。

**元数据** → `00-source/metadata.md`：封面（EPUB/PDF 内嵌封面图则提取；否则网络搜索封面图 URL 存档）、版权页信息、目录结构、版次/出版社/出版年。

**书名输入（无文件）**：联网调研书信息（作者、出版信息、目录、公开书摘与评介）写 `00-source/metadata.md`，并在 metadata.md 顶部标注：`⚠ 无原文模式：本目录所有内容基于网络资料与模型知识，未读原文，引用一律降级处理`。

## 2. 信源标注规则（防幻觉，全流程有效）

- `[原文·<章节/页>]`：直接引自提取文本，必须能在 fulltext.md 里找到
- `[网络·<来源名/URL>]`：搜索所得
- `[推断·<依据>]`：模型推理，须写明依据
- **无原文模式降级**：禁止出现 `[原文·]` 标注；书内容转述一律用 `[网络·]` 或 `[推断·]`；书评中"原文引用"改为"转述"
- 查不到的写「无法核实」，不编造

## 3. 主题分类

读 references/taxonomy.md 执行决策树 → 写 `01-meta/classification.md`（分类卡）。同时判定**特殊标记**：是否含真实历史/地理内容（决定时空审计激活方式）。

**分类卡纪律**：特殊标记必须附证据（Grep 计数/行号），不许凭印象——首拆实战中"价格双轨制"被凭印象标为重要史实，时空审计核实后发现全书仅 2 处且实指医疗双轨制。

## 3.5 全书测绘官（文件模式必配，见 router.md 覆盖策略）

派 1 个子 agent 通读全文 → `01-meta/book-map.md`（逐讲摘要 + 绝对化论断全量清单 + 概念密度表 + 金句表）。专家 prompt 一律附上测绘图。

## 4. 并行调研（4 个 general-purpose 子 agent，单消息同时派发）

每个 agent 的 prompt 必须自带：书名、作者、分类卡内容、输出文件路径、信源规则、WebSearch/WebFetch 使用许可。输出均为 markdown，头部注明信源与检索日期。

| Agent | 使命 | 输出 |
|---|---|---|
| A 作者谱系 | 作者其人：生平要点、其他著作及相互关系、思想/风格演变脉络 | `01-meta/author-spectrum.md` |
| B 同类书目 | 同题材、同主题、同风格的书（各 3-8 本，一句话理由）；**丛书线索：本书所属译丛/系列的已出与后续书目（带丛书名与编号，如「智慧宫 039」）** | `01-meta/related-books.md` |
| C 立场对话书目 | 与本书主旨**意图相同 / 相近 / 相反**的书（相反类重点找：直接反驳或同题异构） | `01-meta/dialogue-books.md` |
| D 背景与争议 | 创作背景、时代语境、出版反响、主要批评与争议点、奖项/榜单 | `01-meta/context.md` |

**丛书落库约定**：丛书系书目进 frontier 时保留丛书标记（如「[智慧宫]」），同丛书第二本起在 LIBRARY/宇宙中可自然聚簇。

- `--no-persona` 跳过；否则读 `universe/persona/profile.md`（不存在 → 视为首拆，step 7 初始化）
