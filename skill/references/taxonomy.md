# 类型体系（taxonomy）

拆书的第一步是分类：类型决定激活哪些专家、每步分析什么、最终产出什么。分类要**快而准**：读目录 + 抽样正文 + 元数据即可判断，不需要通读全书。

## 七大原型类型

| 类型 | id | 子类型示例 | 专家档案 |
|---|---|---|---|
| 虚构叙事 | `fiction` | 严肃文学、科幻、奇幻、推理悬疑、历史小说、武侠、言情、短篇集、戏剧剧本、寓言童话 | experts/fiction.md |
| 非虚构叙事 | `narrative` | 传记、自传、回忆录、纪实文学、报告文学、历史（通俗/学术）、旅行文学、随笔集、书信日记 | experts/narrative.md |
| 思想论述 | `ideas` | 哲学（通俗/学术）、社会科学（社会学/心理学/经济学/政治学）、科普、商业管理、时事评论、杂文 | experts/ideas.md |
| 知识技能 | `knowledge` | 教材、学术专著、技术书（编程/工程）、方法论、自助成长、工具书手册、语言学习 | experts/knowledge.md |
| 诗歌韵文 | `poetry` | 诗集、词集、史诗、散文诗 | experts/arts.md |
| 视觉艺术 | `visual` | 画册、摄影集、图像小说、漫画、艺术理论画册 | experts/arts.md |
| 实用生活 | `practical` | 菜谱、健身、旅行指南、家居、育儿实操、手账方法论 | experts/arts.md（轻量处理） |

## 分类决策树

按顺序问，命中即停：

1. **内容以讲故事为主？**（有情节、有人物命运）
   - 人物与事件是虚构的 → `fiction`，再按题材定子类型
   - 人物与事件真实存在 → `narrative`
2. **内容以提出主张、论证观点为主？**（核心是"我认为……因为……"）
   - → `ideas`（区分：哲学/社科/科普/商业/评论，决定 ideas 档案里领域专家的领域）
3. **内容以传授知识体系或技能为主？**（核心是"学会……"）
   - → `knowledge`
4. **以韵文为主** → `poetry`；**以图像为主** → `visual`；**以可执行操作步骤为主**（照着做）→ `practical`
5. 都不明显 → 选最接近的原型，降置信度，在确认点 A 交用户裁决。

## 混合权重

很多书是混合体。用权重表达，专家组合按权重配置：

```yaml
# 例：《三体》
主类型: fiction (科幻小说)
副类型: ideas (科普)
权重: {fiction: 0.85, ideas: 0.15}
置信度: 高
依据: [目录结构为三部曲叙事, 抽样章节含大量科幻设定阐释]
```

- 副类型权重 ≥ 0.3 → step 2 加读其档案并激活至少 1 名该类专家
- 副类型权重 < 0.3 → 只在相关知识点出现时动态召唤微专家

## 分类卡（输出到 01-meta/classification.md）

```markdown
# 分类：<书名>

- 主类型：<id>（<子类型>）
- 副类型：<id>（<子类型>）
- 权重：{...}
- 置信度：<高|中|低>
- 依据：[原文·目录] / [网络·简介] …
- 激活档案：experts/xx.md（+ experts/yy.md）
- 特殊标记：是否含真实历史/地理内容（决定时空审计激活方式，见 auditor.md）
```

## 注意

- 分类宁可在确认点 A 让用户改，不要假装确定：低置信度就明说。
- 系列书/文集（如短篇集）：按整体定类型，个别篇目特殊可在 step 2 备注。
- `--type` 参数直接跳过本文件流程，但仍要写分类卡（标记"用户指定"）。
