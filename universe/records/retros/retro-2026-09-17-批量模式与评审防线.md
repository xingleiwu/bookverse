## 二、新暴露的问题（按严重度）

### P1 · 主 agent 摘要转述时的「机制脑补」——三连击

| 事件 | 错误 | 根因 |
|---|---|---|
| 迷雾·许霆案 | 威慑机制方向写反（原书：实名卡留痕→破案率近 100%→轻罚即足；我写成：ATM 故障→低破案率→威慑失效） | 测绘摘要只给了「作案方式的破案率结构」，方向未落字，我按直觉补全因果链 |
| 刻意练习·7410 | 「7410@20 岁」时间锚点错位（7410 是 18 岁均值，一万才是 20 岁累计） | context.md 两种口径并存，取数时未回对原始含义 |
| 迷雾·Megrabyan | prompt 里写了「Macnamara & Megrabyan 2019」——查无此文 | 从记忆里给调研 prompt 塞了未核实的文献名 |

**共性**：错误全部发生在主 agent 把二手摘要写成一手陈述的环节，且全部被评审组/调研 agent 回对原文后抓出。digest 层的错误会向书评+6 件 takeaway+概念节点传播 7-8 个文件，修复成本高。

**对策（已回写 skill）**：
1. digest/level1 的**因果链与关键数字必须带 [原文·L行号]**——无行号的机制描述即脑补嫌疑（stage3-digest.md 写作纪律新增第一条）
2. 主 agent 给子 agent 的 prompt 中**只引用已核实文献**，不确定的一律让子 agent 自行核实（SKILL.md 铁律 4）
3. 书评在批量模式下并入评审范围（此前书评靠确认点 B 人工把关，批量模式 B 被跳过后出现空窗）——review-panel.md 更新

### P2 · 批量模式的空窗与暂存

批量模式（用户说「按价值顺序逐个拆」时启用）跳过 A/C、书评初稿即定稿。暴露三点：
- 书评零评审空窗（上条已补）
- **人格提案缺交互信号**：v9/v10 两次提案只有涌现候选，无品味/表达信号（逐段确认才有）——裁决价值降级。已在提案文件标注「只能裁思想立场」
- **暂存机制有效**：proposals/ 目录方案守住了防僭越纪律，但需用户主动想起来裁决。改进：每本书汇报里固定提示「待裁决提案数」

### P3 · 墙钟异常

刻意练习的两个专家 agent 墙钟 8 小时+（practice 8.05h、redteam 8.25h，token 用量正常、产出完整）——疑似多 agent 并发排队。质量无损但拖长批次。对策：后段专家（practice/redteam）本就依赖前段产出，天然串行，无需改；记录在案供排查。

### P4 · 内容过滤的适用面扩展

迷雾书目调研 agent 因案件细节词触发 1301。原降级策略写在 auditor.md（时空审计专用），本次验证它同样适用于调研 agent（中性学术框架重派一次成功）。已把适用面写宽。

## 三、验证有效（继续保持）

1. **小批派单 ≤3/批**：三本约 40 个 agent，零超时折损（对照 9-17 上午 13 派只成 3 的灾难）
2. **骨架先写纪律**：全部长任务 agent 存活，8 小时墙钟的也没产出空
3. **测绘官·目录精测降级**：刻意练习（结构规整方法论书）用目录精测，mapper 仅 1.64M（对照全量 mapper 3.2-4.9M），质量足够供给全部下游——**规整论著默认目录精测**写进 router.md
4. **OCR 路径模板化**：swift 脚本沉淀至 scripts/ocr.swift，186 页/3 分钟，Vision 中文识别质量高（术语零误识），stage1-research.md 已更新
5. **BATCH-PROGRESS.md**：跨上下文压缩的批次状态锚，两次压缩后无损恢复
6. **书库对照脚本**：frontier 📚 标记 + 待归档直拆队列，把「拆什么」的决策成本降为零
